วันที่: 2026-10-11 · สถานะ: อนุมัติแผนแล้ว รอผู้ใช้ดู wireframe ก่อนเขียนโค้ด
อ้างอิง: `docs/19-quality-research.md` · Linear P-KAN-1

## 0. ขอบเขตและหลักการ

- **ขอบเขต:** ข้อมูลมหาวิทยาลัย (ต้นน้ำ) → ค้นหา ตัดสินใจ สมัคร → ผลรับเข้า วีซ่า ถึงจีน (ปลายน้ำ)
- **ตลาด:** จีน ปริญญาตรี แต่โครงสร้างข้อมูลรองรับการเพิ่มประเทศและระดับการศึกษาได้ โดยไม่ต้องเปลี่ยน schema
- **ไม่อยู่ในรอบนี้:** โมเดลธุรกิจ, community, mentor, housing, การยื่นใบสมัครแทนผู้ใช้
- **วิธีทำ:** ออกแบบใหม่ทั้งระบบก่อน แล้วย้ายโค้ดเดิมทีละขั้น ใช้ stack เดิม (Next / React / TS / pg / Better Auth) และ `npm run verify` ต้องผ่านทุกขั้น

**กฎที่คงไว้**
- แหล่งทางการเป็นผู้ยืนยันข้อเท็จจริง AI ช่วยอธิบาย
- unknown ต้องคงเป็น unknown
- ข้อมูลรอบ 2026 ห้ามถูกเลื่อนเป็นรอบ 2027
- แยก admissions ทั่วไป / international / graduate ออกจากกัน
- ห้ามรับประกันผลรับเข้า
- คุ้มครองผู้ใช้อายุต่ำกว่า 18 ปี

**หลักการออกแบบ**
1. **หนึ่งหน้าจอ หนึ่ง next action** ผู้ใช้ต้องบอกได้ภายใน 10 วินาทีว่าขั้นต่อไปของตัวเองคืออะไร
2. **ความจริงก่อนความครบ** ข้อมูลที่ยังไม่รู้ต้องแสดงอย่างนุ่มนวลและตรงไปตรงมา ไม่ดูเหมือน error
3. **สงบตา** ใช้สีน้อย ตัวอักษรไทย 16px ขึ้นไป line-height 1.6 พื้นที่ว่างมาก ปุ่มกดได้ขนาด 44px ขึ้นไป

## 5. หน้าจอหลัก

**การ์ดหลักสูตร**
- ชื่อหลักสูตร, มหาวิทยาลัย, เมือง, ภาษาที่สอน
- chip สถานะ **อันเดียว**: `ยืนยันแล้ว` / `รอตรวจสอบ` / `ข้อมูลขัดกัน` / `มีแค่ข้อมูลรอบ 2026`
- ข้อมูลสองตัวที่ใช้ตัดสินใจ: วันปิดรับ และค่าเรียน
- ตัดป้าย meta ที่ซ้อนกันออก

**รายละเอียดหลักสูตร**
1. แผง "ฉันสมัครได้ไหม" ใช้ `eligibility()` แสดงผลแต่ละข้อเป็น ผ่าน / ยังขาด / ยังไม่รู้
2. ข้อความรอบที่ตรงไปตรงมา เช่น "รอบ 2027 ยังไม่ประกาศ · รอบ 2026 ปิด 28 ก.พ. (ใช้กะเวลาได้)"
3. การ์ด CSCA: วิชาที่ต้องสอบตามสาขาและภาษาที่เรียน
4. ทุน, เอกสาร, แหล่งอ้างอิงพร้อมวันที่ตรวจ

**แผนสมัคร**
- การ์ด "ขั้นต่อไป" ใหญ่หนึ่งใบ
- timeline ตามวันที่
- รายการ "รอยืนยัน"
- ส่งออกเป็น `.ics`

**Arrival**
- checklist 8 ขั้น แต่ละขั้นมีแหล่งทางการ หรือข้อความ "ตรวจกับมหาวิทยาลัยของคุณ"

**Design system**
- `next/font` Noto Sans Thai, base 16px/1.6, touch target 44px ขึ้นไป
- token สีที่ผ่าน WCAG 2.2 AA + dark mode
- เขียน `globals.css` ใหม่ให้อ่านได้
- แนวทางอ้างอิง: GOV.UK task list pattern, NN/g

## 6. ต้นน้ำ: ข้อมูล

### 6.1 Status ladder เดียว (สถาบัน → fact)

| สถานะใน discovery (สถาบัน) | ในแอป |
|---|---|
| `not_checked` | ไม่แสดง |
| `source_found` | "กำลังเตรียมข้อมูล" ยังไม่มี fact |
| `not_verified` | fact เป็น draft เผยแพร่ได้หลังผ่าน review |
| `no_current_admissions` | "ไม่เปิดรับรอบนี้" (ผูกกับรอบ) |
| `verified_admissions` | สร้าง Program ได้ แต่แต่ละ fact ยังต้องได้ verified เอง |

- Fact ยังใช้ `verified` / `unknown` / `conflict` ตาม `web/src/lib/provenance.ts` และเพิ่ม `stale` (แหล่งเปลี่ยนหลังวันที่ตรวจ)
- Fact รอบ 2026 ติดป้าย 2026 เสมอ และไม่ถูกคัดลอกเป็น 2027

### 6.2 Relational model (ทำตาม `docs/07`; ต้องขออนุมัติก่อนแตะ schema)

```
Country ─< Institution(moe_code) ─< Program(level, admission_track, language)
Program ─< ProgramCycle >─ Cycle(year, season, round)
ProgramCycle ─< Requirement(type: language|csca_subject|qualification|document|deadline|tuition)
Requirement / ProgramCycle ─< Fact(value, status, reason, reviewer, verified_at) ─< Evidence(url, locator, retrieved_at)
Source ─< SourceVersion(hash) → ReviewItem(fact_id)
ArrivalStep(country) ─< Fact
```

- ประเทศและระดับการศึกษาเป็นคอลัมน์ ไม่ต้องสร้างตารางใหม่เมื่อขยาย
- ทำ repository layer ที่คืน type `Program` เดิม เพื่อไม่ต้องแก้ `domain.ts` และ `discovery.ts`

### 6.3 Pipeline

| ขั้น | ตอนนี้ |
|---|---|
| Source (นำเข้าจาก discovery SQLite) | สคริปต์ (ต้องสร้าง) |
| Capture (hash แหล่ง) | อัตโนมัติ มีแล้ว: `sources.ts`, `api/cron/sources` |
| AI extraction | ทำภายหลัง สร้างได้แค่ draft |
| Normalize / validate | อัตโนมัติด้วย zod + กฎรอบ (บล็อก 2026→2027) |
| Human review | ทุก fact |
| Publish | อัตโนมัติหลังอนุมัติ |

### 6.4 Admin ขั้นต่ำ
- คิวงานที่กรองได้ตาม stale / conflict / new
- หน้า item แสดง diff ของแหล่ง, ฟอร์ม fact, locator, ปุ่ม approve / reject
- หน้า coverage: ตารางสถาบัน × สถานะ
- route ที่ยังว่างต้องเขียน: `api/admin/reviews/[id]/publish`, `api/admin/sources/[id]`
