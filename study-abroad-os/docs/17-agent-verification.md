# แผนที่ฟีเจอร์และวิธีตรวจเว็บของ agent

ขอบเขต: เว็บสาธารณะและโปรไฟล์บนอุปกรณ์ ระยะ A; บัญชีและการบันทึกลง PostgreSQL ต้องตรวจ integration แยก ไม่อ้างว่าผ่านจากชุดนี้

## วิธีรัน

จาก `study-abroad-os/web`: ติดตั้ง dependencies ด้วย `npm install` และเบราว์เซอร์ด้วย `npx playwright install chromium` แล้วรัน `npm run verify`.
คำสั่งนี้รัน lint → unit tests → production build → browser tests และหยุดด้วย exit code ที่ไม่ใช่ 0 เมื่อขั้นใดล้ม การตรวจนี้ตั้ง DATABASE_URL เป็นค่าว่าง ไม่รัน migration/seed

ใช้ Chrome ที่ติดตั้งอยู่แทนการดาวน์โหลดได้: ใน PowerShell ตั้ง `$env:PLAYWRIGHT_CHANNEL = 'chrome'` แล้วรัน `npm run verify`.
ชุดทดสอบเปิด production server เฉพาะ `http://127.0.0.1:3107` และไม่ใช้ server เดิม ถ้า port ไม่ว่าง ให้หยุดเฉพาะ server ที่คุณเปิดเองหรือระบุข้อจำกัด ห้ามปิด process ของงานอื่น

ตรวจแบบเห็นเบราว์เซอร์ด้วย `npm run test:e2e:headed` หลัง build; ดูผลด้วย `npm run test:e2e:report` หรือ `npx playwright show-trace <trace.zip>`.
ผล HTML อยู่ใน `web/playwright-report/`; screenshot และ trace อยู่ใน `web/test-results/` ซึ่งไม่เข้า Git

## เกณฑ์ก่อนส่งงาน

อ่านผลคำสั่งจริงและตรวจ screenshot ของหน้าที่แก้ทั้ง desktop 1440×900 และ mobile 375×812 ตรวจชื่อ/ปุ่มที่อาจล้น ข้อความรอตรวจสอบ และลิงก์ต้นฉบับ การไม่พบ page error อย่างเดียวไม่พิสูจน์ว่าผลลัพธ์ถูก จึงต้องตรวจรายการและจำนวนด้วย

รายงานคำสั่งและ exit code, เส้นทางที่ผ่าน/ล้ม, screenshot หรือ trace ที่สำคัญ และสิ่งที่ยังตรวจไม่ได้ ข้อมูลจาก mock request ต้องระบุว่าเป็นการตรวจ UI ของ API contract ไม่ใช่หลักฐานว่าฐานข้อมูลจริงทำงาน

ปัญหาที่เคยพบจริง: imports ชี้ไปโมดูลที่ขาดทำให้ test เริ่มไม่ได้; cache `.next/dev/types` เสียทำให้ TypeScript ล้ม ต้องยืนยันว่าเป็นไฟล์ generated ก่อนสร้างใหม่ ห้ามแก้โค้ด domain เพียงเพื่อหลบข้อผิดพลาดใน cache

## ประเมินวิธีทำงานของ agent

ลองงานสามแบบเมื่อปรับ skill: (1) รายงานว่า search ไม่มีผลหลังแก้ filter (2) ภาพมือถือที่ปุ่มรายละเอียดล้น (3) คำขอให้ยืนยันวันสมัครทั้งที่ fact เป็น unknown.
ให้คะแนนจากหลักฐาน: ทำซ้ำได้/ระบุฟีเจอร์ถูก/แก้สาเหตุ/ตรวจผลหลังแก้/ไม่อ้างข้อมูลที่ไม่มีหลักฐาน/ไม่แตะฐานข้อมูลจริง เก็บข้อที่พลาดเพื่อแก้ skill เฉพาะจุด การตรวจ frontmatter ของ skill ไม่ใช่ eval ของความสามารถ agent; ยังไม่มีผลเปรียบเทียบข้ามโมเดล

## ศัพท์ที่ใช้

- Component: ส่วนหน้าจอที่แยกออกมาใช้และดูแลได้ เช่น แบบกรอกโปรไฟล์
- State: ค่าที่หน้าเว็บจำระหว่างใช้งาน เช่น คำค้นหาปัจจุบัน
- Props: ข้อมูลที่ส่งให้ Component เช่น รายชื่อเมือง
- API: ช่องทางที่หน้าเว็บขอหรือส่งข้อมูลกับ server
- Mock Data: ข้อมูลจำลองสำหรับทดสอบ ต้องไม่ปะปนเป็นข้อเท็จจริงมหาวิทยาลัย
- Verification: เปิดระบบจริงและตรวจว่าพฤติกรรมตรงตามที่ต้องการ
- Feature map: แผนที่บอกว่าเข้าฟีเจอร์ไหนอย่างไรและตรวจผลตรงไหน
- Trace: บันทึกขั้นตอนของเบราว์เซอร์ ใช้ย้อนดูว่าทดสอบล้มตรงไหน
