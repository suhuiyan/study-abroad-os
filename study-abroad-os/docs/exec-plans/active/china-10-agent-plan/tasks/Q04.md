# Q04: ดำเนิน usability test กับผู้ทดลองจริงห้าคน

TASK ID: Q04
ชื่อสั้นของงาน: ดำเนิน usability test กับผู้ทดลองจริงห้าคน
ประเภท: usability
สถานะ: PLANNED (ใบงานนี้ยังไม่ได้ดำเนินการ)

## เป้าหมาย
ดำเนิน usability test กับผู้ทดลองจริงห้าคน เพื่อให้ส่วนงานนี้ตรวจรับได้ตามเกณฑ์ด้านล่างและส่งต่อให้ task ที่พึ่งพา โดยใช้ระบบ MVP เดิม.

## ขอบเขต
1. รอเจ้าของโครงการจัดผู้ทดลองและยืนยัน staging candidate; ไม่ส่งอีเมลเชิญหรือข้อความเอง
2. ให้ผู้ทดลองทำตาม protocol โดยผู้สังเกตจด anonymized ID/งาน/ผล/จุดติด
3. สรุป issue แบบ reproducible steps, expected/actual, severity, route, screenshot ที่ไม่มีข้อมูลส่วนตัว
4. ส่ง verdict ผ่าน/ไม่ผ่าน/ยังไม่ครบ; ถ้าพบ blocker ให้ coordinator เปิดใบงานแก้หนึ่งปัญหาต่อ Agent แล้วทดสอบซ้ำก่อน Q05

## นอกขอบเขต
ไม่แก้เรื่องอื่นใน roadmap, ไม่ refactor ทั้งแอป, ไม่เปลี่ยน provider/architecture, ไม่เพิ่มมหาวิทยาลัยเกินชุดแรก.
ไม่เข้าหรือแก้ production, ไม่ push main/deploy, ไม่อ่านหรือขอ production secrets.
งานนี้เน้นเอกสาร/หลักฐาน/ตรวจรับ; ห้ามแก้ application code เว้นแต่ write allowlist ระบุไว้.

## บริบทที่จำเป็น
เป้าหมายผู้ใช้: นักเรียนไทยสมัครปริญญาตรีจีน. สิบรายการปัจจุบันเป็นสิบเส้นทางตั้งต้น ไม่ใช่ทุกสาขา.
Baseline ที่ตรวจ: 630a2b1; coordinator ต้องส่ง BASE_COMMIT ที่รวม dependencies แล้วในวันเริ่มงาน.
เหตุผลจาก baseline/ความเสี่ยงที่ต้องจัดการ: ต้องอาศัยคนจริง; ห้ามปลอมผลเพื่อปิดงาน
ต้องอ่านผลที่ผ่านตรวจของ Q02, Q03 ก่อนลงมือ. ไฟล์ใหม่ใน read list จะเกิดจาก dependency; ห้ามสมมติว่ามีแล้วใน baseline.

## Acceptance Criteria
- [ ] มีผลจริง 5 คนและหลักฐานแต่ละงาน ไม่เอา simulation มานับ
- [ ] อย่างน้อย 4/5 ทำ flow จบ และไม่มี critical misunderstanding ที่ค้างเพื่อให้ผ่าน
- [ ] หากผู้ทดลองยังไม่มีให้ BLOCKED พร้อมจำนวนที่ขาด
- [ ] feature requests แยก backlog ไม่ขยาย scope อัตโนมัติ
- [ ] diff อยู่ใน allowlist; prerequisite version ถูกต้อง; รายงานแยก PASS/FAIL/NOT_RUN และขอ READY_FOR_REVIEW.

## คำสั่งตรวจสอบ
- `git diff --check`
- manual: cross-check 5 anonymous scorecards กับ aggregate และ issue verdict
npm/npx ใช้ cwd `study-abroad-os/web`; git ใช้ repo root. คำสั่งที่เพิ่มโดย upstream ต้องมีจริงก่อนรัน.
ไม่มี test ของ application จำเป็นสำหรับงานเอกสาร/research ล้วน; ใช้ evidence/manual review ตามที่ระบุ. อย่าอ้างว่า test ผ่านถ้าไม่ได้รัน.

## กรณีผิดพลาด
ยังไม่มีผู้ทดลองจริง: BLOCKED พร้อมสิ่งที่ขาด; ทำ protocol ให้พร้อมแต่ห้ามสร้างผลทดสอบปลอม.
เก็บ changes ที่อยู่ใน scope ไว้ให้ตรวจ ห้ามล้างของคนอื่น. ให้ผู้ประสานงานตัดสินใจส่วนที่เกินขอบเขต.
