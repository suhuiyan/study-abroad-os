# L02: ปล่อย candidate และตรวจข้อมูลจริงโดย release owner

TASK ID: L02
ชื่อสั้นของงาน: ปล่อย candidate และตรวจข้อมูลจริงโดย release owner
ประเภท: deployment
สถานะ: PLANNED (ใบงานนี้ยังไม่ได้ดำเนินการ)

## เป้าหมาย
ปล่อย candidate และตรวจข้อมูลจริงโดย release owner เพื่อให้ส่วนงานนี้ตรวจรับได้ตามเกณฑ์ด้านล่างและส่งต่อให้ task ที่พึ่งพา โดยใช้ระบบ MVP เดิม.

## ขอบเขต
1. ให้ผู้รับผิดชอบ release ที่ได้รับมอบหมายทำ production actions ผ่าน session ที่มีสิทธิ์; Agent เล็กได้เฉพาะผลที่ redact แล้ว
2. ตรวจ backup/migration/candidate SHA แล้ว deploy ตาม runbook; ไม่นับการจัดทำแผนนี้เป็นคำสั่ง deploy
3. สร้าง/review/publish draft จาก D02 manifest ผ่าน admin ทีละรายการตาม verdict; seed จะไม่ update DB เดิม
4. ตรวจ HTTP/anonymous API/catalog10/session/shortlist/plan ด้วย controlled test account; ตรวจ actual cron run history ไม่อนุมานจาก vercel.json
5. บันทึก release result และเงื่อนไข rollback; ถ้าไม่มีสิทธิ์หรือเกิด blocker ให้หยุดเฉพาะ release

## นอกขอบเขต
ไม่แก้เรื่องอื่นใน roadmap, ไม่ refactor ทั้งแอป, ไม่เปลี่ยน provider/architecture, ไม่เพิ่มมหาวิทยาลัยเกินชุดแรก.
ทำเฉพาะ release ตาม RUNBOOK ที่ผ่าน review แล้ว; ไม่ publish โดยไม่มี authority.


## บริบทที่จำเป็น
เป้าหมายผู้ใช้: นักเรียนไทยสมัครปริญญาตรีจีน. สิบรายการปัจจุบันเป็นสิบเส้นทางตั้งต้น ไม่ใช่ทุกสาขา.
Baseline ที่ตรวจ: 630a2b1; coordinator ต้องส่ง BASE_COMMIT ที่รวม dependencies แล้วในวันเริ่มงาน.
เหตุผลจาก baseline/ความเสี่ยงที่ต้องจัดการ: งานนี้ใช้ production access จึงมอบ release owner เท่านั้น ไม่ dispatch ให้ worker โมเดลเล็ก
ต้องอ่านผลที่ผ่านตรวจของ L01 ก่อนลงมือ. ไฟล์ใหม่ใน read list จะเกิดจาก dependency; ห้ามสมมติว่ามีแล้วใน baseline.
