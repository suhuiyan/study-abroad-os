# Q01: ตรวจสิทธิ์และ flow ข้อมูลร่วมกันใน integration suite

TASK ID: Q01
ชื่อสั้นของงาน: ตรวจสิทธิ์และ flow ข้อมูลร่วมกันใน integration suite
ประเภท: testing
สถานะ: PLANNED (ใบงานนี้ยังไม่ได้ดำเนินการ)

## เป้าหมาย
ตรวจสิทธิ์และ flow ข้อมูลร่วมกันใน integration suite เพื่อให้ส่วนงานนี้ตรวจรับได้ตามเกณฑ์ด้านล่างและส่งต่อให้ task ที่พึ่งพา โดยใช้ระบบ MVP เดิม.

## ขอบเขต
1. ใช้ DB ทิ้งได้ fixture users A/B/admin และ token เทียม; แยก session requests ให้ชัด
2. ทดสอบ source changed -> draft -> review -> publish -> workspace -> eligibility และ application persistence
3. negative matrix: anonymous/member/admin, malformed body, bad origin, wrong owner, stale versions, rejected review
4. inject failure ระหว่าง transaction และ replay request แล้วตรวจ row counts/revisions

## นอกขอบเขต
ไม่แก้เรื่องอื่นใน roadmap, ไม่ refactor ทั้งแอป, ไม่เปลี่ยน provider/architecture, ไม่เพิ่มมหาวิทยาลัยเกินชุดแรก.
ไม่เข้าหรือแก้ production, ไม่ push main/deploy, ไม่อ่านหรือขอ production secrets.


## บริบทที่จำเป็น
เป้าหมายผู้ใช้: นักเรียนไทยสมัครปริญญาตรีจีน. สิบรายการปัจจุบันเป็นสิบเส้นทางตั้งต้น ไม่ใช่ทุกสาขา.
Baseline ที่ตรวจ: 630a2b1; coordinator ต้องส่ง BASE_COMMIT ที่รวม dependencies แล้วในวันเริ่มงาน.
เหตุผลจาก baseline/ความเสี่ยงที่ต้องจัดการ: unit tests เดิมไม่พิสูจน์ DB ownership/atomicity; ใช้ real disposable PostgreSQL
ต้องอ่านผลที่ผ่านตรวจของ S04, A03, E03, P02 ก่อนลงมือ. ไฟล์ใหม่ใน read list จะเกิดจาก dependency; ห้ามสมมติว่ามีแล้วใน baseline.

## Acceptance Criteria
- [ ] ไม่มี cross-user read/write หรือ non-admin publish
- [ ] publishing failure ไม่เปลี่ยน published facts ครึ่งทาง
- [ ] cron error ไม่เปลี่ยน catalog
- [ ] ชุดทดสอบรันซ้ำได้และ cleanup เฉพาะ test namespace
- [ ] diff อยู่ใน allowlist; prerequisite version ถูกต้อง; รายงานแยก PASS/FAIL/NOT_RUN และขอ READY_FOR_REVIEW.
