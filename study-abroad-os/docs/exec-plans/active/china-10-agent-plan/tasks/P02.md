# P02: ป้องกันการบันทึกทับกันของแผนสมัคร

TASK ID: P02
ชื่อสั้นของงาน: ป้องกันการบันทึกทับกันของแผนสมัคร
ประเภท: coding
สถานะ: PLANNED (ใบงานนี้ยังไม่ได้ดำเนินการ)

## เป้าหมาย
ป้องกันการบันทึกทับกันของแผนสมัคร เพื่อให้ส่วนงานนี้ตรวจรับได้ตามเกณฑ์ด้านล่างและส่งต่อให้ task ที่พึ่งพา โดยใช้ระบบ MVP เดิม.

## ขอบเขต
1. เพิ่ม application version แบบ additive พร้อม default ให้ row เก่า
2. ให้ application update ใช้ expectedVersion และตอบ 409 เมื่อ stale; response คืน version ใหม่
3. ใช้ targeted updates หรือ merge contract ที่กำหนด ไม่ปล่อย whole-object last write wins
4. ทดสอบสองแท็บแก้ notes/tasks/status และ mixed old-client request

## นอกขอบเขต
ไม่แก้เรื่องอื่นใน roadmap, ไม่ refactor ทั้งแอป, ไม่เปลี่ยน provider/architecture, ไม่เพิ่มมหาวิทยาลัยเกินชุดแรก.
ไม่เข้าหรือแก้ production, ไม่ push main/deploy, ไม่อ่านหรือขอ production secrets.


## บริบทที่จำเป็น
เป้าหมายผู้ใช้: นักเรียนไทยสมัครปริญญาตรีจีน. สิบรายการปัจจุบันเป็นสิบเส้นทางตั้งต้น ไม่ใช่ทุกสาขา.
Baseline ที่ตรวจ: 630a2b1; coordinator ต้องส่ง BASE_COMMIT ที่รวม dependencies แล้วในวันเริ่มงาน.
เหตุผลจาก baseline/ความเสี่ยงที่ต้องจัดการ: request ช้ากว่าอาจทับ note ใหม่; optimistic version gate และ UI recovery ใน P03
ต้องอ่านผลที่ผ่านตรวจของ P01 ก่อนลงมือ. ไฟล์ใหม่ใน read list จะเกิดจาก dependency; ห้ามสมมติว่ามีแล้วใน baseline.

## Acceptance Criteria
- [ ] สอง update version เดียวมีได้หนึ่ง success อีกหนึ่ง conflict
- [ ] server ไม่เปลี่ยน notes เมื่อ update checkbox เท่านั้น
- [ ] legacy GET คืน version ที่ใช้ได้; legacy mutation ที่ไม่มี version ต้องมี error อธิบายชัด
- [ ] ไม่มีข้อมูลเดิมหายเมื่อ migration ซ้ำ
- [ ] diff อยู่ใน allowlist; prerequisite version ถูกต้อง; รายงานแยก PASS/FAIL/NOT_RUN และขอ READY_FOR_REVIEW.
