# ส่งมอบหน้าเว็บระยะ A

วันที่: 2026-10-07 · ขอบเขตตาม `16-web-experience-handoff.md`

## ก่อนและหลัง

เดิมมีรายการเริ่มต้น 10 มหาวิทยาลัยจาก `web/src/lib/catalog.ts`, ค้นหา/กรอง, รายละเอียด, ทุน, โปรไฟล์, ที่บันทึก และแผนสมัครที่เชื่อมบัญชีแล้ว แต่ยังขาดการเริ่มต้นสั้น ๆ, โปรไฟล์ guest ที่แก้ได้, เหตุผลการเรียงผล, การรับมือ API ผิดรูปแบบ และชุดตรวจเบราว์เซอร์ที่ทำซ้ำได้ บาง import ชี้ไปโมดูลที่ยังไม่มี ทำให้ตรวจโค้ดไม่ได้

ตอนนี้ผู้ใช้ข้ามแบบเริ่มต้นได้โดยไม่สมัครบัญชี หรือกรอกข้อมูลการศึกษาเพื่อเรียงตัวเลือกพร้อมเหตุผล ค้นหาชื่อไทย/จีน/อังกฤษ กรองเมือง/สาขา/รายการที่มีข้อมูลทุน และล้างตัวกรองได้ ย้ายการตั้งค่าภาษาเรียนออกจากแถบค้นหาและแบบเริ่มต้นไปไว้ในเมนู “ตั้งค่า” ค่านี้ยังใช้เรียงคำแนะนำและบันทึกบนอุปกรณ์ เปิดรายละเอียดที่แสดงแหล่งทางการ วันที่ตรวจ และเรื่องที่รอตรวจสอบได้ โปรไฟล์ guest เก็บบนอุปกรณ์ กลับมาแก้หรือลบได้ มีข้อความเมื่อ browser ไม่อนุญาตให้เก็บข้อมูล

ใช้ข้อมูล catalog ที่มีอยู่ ไม่เติมข้อเท็จจริงหรือเปลี่ยนวันที่ตรวจมหาวิทยาลัย ข้อมูลประกาศเก่ายังคงติดรอบเดิม ไม่ยืนยันเกณฑ์หรือค่าเรียนของปีใหม่จากปีเก่า ข้อมูลจำลองใช้เฉพาะทดสอบความผิดพลาดของ API และการเปิดลิงก์ ไม่เผยแพร่เป็นข้อเท็จจริง

## ผลการตรวจ

รอบก่อนสุดท้าย `npm run verify` ผ่าน exit 0: lint, unit 13/13, production build และ browser 16/16 หลังจากแก้ locator ในชุดทดสอบและแยกรายงาน generated ออกจาก lint

รอบส่งมอบสุดท้าย `npm run verify`: exit 0; lint ผ่าน, unit 13/13, production build ผ่าน (Next 16.3.8), browser 18/18 ผ่าน รวม loading, ค้นหาภาษาไทย/จีน และ Tab focus จอคอม/มือถือ ใช้ Chrome จริงในโหมด headless และ viewport จำลอง ไม่ใช่การตรวจบนโทรศัพท์จริง

ชุด browser ใช้ desktop 1440×900 และ mobile 375×812 พร้อมตรวจหน้า 320px เพิ่ม ทดสอบ onboarding/skip, เหตุผลเรียงผล, โปรไฟล์แก้/โหลดใหม่/ลบ, ค้นหาและตัวกรอง AND, empty/reset, รายละเอียด/แหล่งข้อมูล/วันที่/ปุ่ม/ลิงก์, error/retry, API รูปแบบผิดและรายการว่าง, localStorage ถูกปิด และบัญชี guest ไม่แสดงว่าบันทึกสำเร็จ

ตรวจภาพ onboarding, รายการ, รายละเอียด และโปรไฟล์จาก `web/test-results/` แล้ว ภาพและรายงานเป็นไฟล์ generated ไม่เข้า Git รายงาน HTML อยู่ `web/playwright-report/` เปิดด้วย `npm run test:e2e:report`

ถ่ายภาพส่วนต้นรายละเอียดเพิ่มจาก local preview ทั้งสองขนาด: `web/test-results/delivery-desktop-overview.png` และ `delivery-mobile-overview.png` ตรวจปุ่ม/ชื่อยาว/รอบ/ค่าเรียนที่รอตรวจ และใช้ screenshot ปิด animation เพื่อไม่จับภาพกลางการเลื่อนเมนูมือถือ

เปิด preview ที่ `http://127.0.0.1:3000` โดย DATABASE_URL ว่าง ตรวจ GET หน้าแรก status 200 และ `/api/workspace` ได้ 10 รายการ, catalogSource bundled, configured false ไม่มีการ deploy

`npm audit --omit=dev --json`: exit 0, ไม่พบช่องโหว่ dependencies ที่ใช้รันแอปในรายงานขณะตรวจ ส่วน audit รวม dev ยังมี high 5 รายการในสาย ESLint/glob และเสนอเปลี่ยน major ย้อนกลับ จึงไม่บังคับแก้แบบเสี่ยงทำลายเวอร์ชัน ต้องทบทวน tooling ก่อนใช้กับไฟล์ที่ไม่น่าเชื่อถือ

## ปรับตามความเห็นในหน้าเว็บ

ย้ายตัวเลือกภาษาเรียนออกจากตัวกรองในหน้าสำรวจและแบบเริ่มต้น ไปไว้ในเมนู `ตั้งค่า` ตามคำขอ ใช้จัดลำดับคำแนะนำต่อได้ บันทึกบนอุปกรณ์ และกลับมาอยู่ค่าที่เลือกหลัง refresh. รัน `npm run verify` หลังแก้ผ่านครบ; ภาพตั้งค่าคอม/มือถืออยู่ `web/test-results/delivery-desktop-settings.png` และ `delivery-mobile-settings.png`.

## ขอบเขตหลักฐานและสิ่งที่รอ

- ผลนี้พิสูจน์เว็บสาธารณะและโปรไฟล์บนอุปกรณ์ ไม่พิสูจน์ login/shortlist/แผนสมัครบน PostgreSQL จริง บริการแผนสมัครตรวจด้วย PGlite ที่สร้างเฉพาะในหน่วยทดสอบ ไม่ใช่ฐานข้อมูล production
- ตัวทดสอบเปิดลิงก์ปลายทางผ่าน route fixture จึงพิสูจน์ปุ่ม/URL/แท็บใหม่ แต่ไม่รับรองว่าเว็บมหาวิทยาลัยออนไลน์หรือข้อมูลต้นฉบับยังไม่เปลี่ยน
- ต้องเติม Program ตาม schema ใน `domain.ts` พร้อม cycle/facts/evidence ผ่านกระบวนการตรวจข้อมูลจริง API ส่ง Workspace ตาม `workspace.ts` แล้ว UI ใช้ต่อได้
- preference เมือง/ภาษา/ทุนเก็บบนอุปกรณ์ ยังไม่ได้สร้างตารางเก็บข้ามอุปกรณ์ โปรไฟล์บัญชีใช้ทางเชื่อมเดิม
- `test:integration`, `test:integration:local` และ `db:seed` เดิมอ้างไฟล์ที่ยังไม่มี ไม่ได้ทำให้พร้อมหรือรันในงานระยะ A
- AI ตรวจเอกสาร, ช่วยกรอกเว็บภายนอก, รับอีเมลและฉลองผลตอบรับยังเป็น roadmap ระยะ B–D ไม่ได้อ้างว่าสร้างแล้ว

## ศัพท์สำหรับเริ่มเขียนโปรแกรม

- Component: ชิ้นส่วนหน้าจอ เช่น แบบกรอกข้อมูล ที่แยกไว้ดูแลง่าย
- State: ค่าที่หน้าเว็บจำระหว่างใช้งาน เช่น คำค้นหาหรือช่องที่กำลังแก้
- Props: ข้อมูลที่ส่งเข้า Component เช่น รายชื่อเมือง
- API: ช่องทางขอและส่งข้อมูลระหว่างหน้าเว็บกับ server
- Mock Data: ข้อมูลจำลองสำหรับทดสอบ ต้องไม่แสดงปะปนเป็นข้อมูลมหาวิทยาลัยจริง
- Schema: กฎกำหนดว่าข้อมูลมีช่องอะไรและรับค่าแบบไหน
- Verification: การตรวจจากผลรันจริง ไม่ใช่ดูโค้ดแล้วคาดว่าทำงาน
